# v2 08 评测回归与基线

> 本节回答：改动之后，怎么确定"效果没变差"。

## 8.1 为什么评测必须"回归"（而不是只跑一次）

RAG 系统是概率性的：chunk 大小、embedding 模型、top_k、重排、prompt
任何一处改动都可能悄悄拉低效果。**没有基线对比，你无法判断一次改动
是变好还是变差**——"看起来还行"和"数据上确实行"是两回事。

## 8.2 流程：建立基线 → 改动 → 跑回归 → 门禁

```
第一次（建立基线）：
  python scripts/05_eval.py --all --out data/baseline.json

之后每次改动：
  python scripts/05_eval.py --all --out data/current.json
  python scripts/admin/check_regression.py --current data/current.json
  # 指标回退超阈值 → 门禁 FAIL → 禁止上线
```

## 8.3 基线长什么样

```json
{
  "hit_rate": 1.0,
  "mrr": 1.0,
  "answer_hit": 1.0,
  "n": 10
}
```

| 指标 | 含义 | 满分 |
|---|---|---|
| hit_rate | 黄金文档是否出现在召回 top-k | 1.0 |
| mrr | 黄金文档排名的倒数均值 | 1.0 |
| answer_hit | 回答是否命中关键信息（LLM 裁判） | 1.0 |

## 8.4 门禁脚本（`admin/check_regression.py`）

```python
for key in ("hit_rate", "mrr", "answer_hit"):
    b = base.get(key, 0)
    c = cur.get(key, 0)
    drop = b - c
    if drop > args.tolerance:   # tolerance 默认 0.02（2%）
        failed = True
        print(f"  {key} 基线={b:.3f} 当前={c:.3f} 回退={drop:.3f} -> FAIL")
```

**为什么用"回退幅度"而不是"绝对分"**：
绝对分看"好不好"，回退看"改了以后有没有退步"。上线审查关心的是后者——
哪怕当前分 0.9，只要和基线一致就说明改动没有破坏效果。

**为什么容忍 2%**：评测本身有波动（LLM 裁判、检索随机性），
零容忍会把"正常波动"误判成"回退"。容忍度要按实测波动设。

## 8.5 为什么用 LLM 当裁判（answer_hit）

答案没有唯一解，无法用正则匹配"对不对"。用 DeepSeek 判断"回答是否
包含关键信息"——**LLM-as-Judge**：
- 优点：零额外标注成本，语义判断
- 风险：裁判和生成用同一模型，可能"自我认同偏差"（生产可换不同模型当裁判）

## 8.6 运行与验证

```bash
# 建立基线（v2 实测全满分）
python scripts/05_eval.py --all --out data/baseline.json
# 结果: HitRate=1.00 | MRR=1.000 | AnswerHit=1.00（10题）

# 正常情况：对比自身 → OK
python scripts/admin/check_regression.py --current data/baseline.json
# 变差情况：模拟低分 → FAIL 阻断
python -c "import json; json.dump({'hit_rate':0.5,'mrr':0.3,'answer_hit':0.4}, open('data/current.json','w'))"
python scripts/admin/check_regression.py --current data/current.json
```

## 8.8 思考题

❓ 问题：为什么"回退检测"比"绝对分达标"更适合上线审查？
💡 为什么这么问：区分"质量高低"和"改动影响"两个维度。
🔍 参考思路：绝对分受评测集质量影响大（出题太简单全满分没区分度），
   回退检测关注的是"这一次改动有没有破坏已建立的基线"，更贴合工程决策。

❓ 问题：LLM 当裁判的"自我认同偏差"具体指什么？怎么缓解？
💡 为什么这么问：LLM-as-Judge 是流行做法但有不诚实风险。
🔍 参考思路：裁判模型可能偏爱自己的风格/自己会答错的点。
   缓解：换模型当裁判、多模型投票、抽人工复核、固定裁判 prompt。

❓ 问题：评测集本身会不会过时？维护策略是什么？
💡 为什么这么问：数据会变，评测集不更新，门禁就失去意义。
🔍 参考思路：文档更新后旧题答案可能变了 → 定期评审评测集；
   从用户反馈回流新题（用户点踩的问题自动进候选）；删除过时题。
